# Manual Nonrecommended Candidates Design

## Goal

差し替え・空き枠割り当ての候補選択で、通常は安全な候補だけを表示しつつ、例外対応時だけ入力サポートを解除して非推奨候補も選べるようにする。

## User Experience

- 差し替えまたは割り当て欄を開いた直後は、従来通り通常候補だけを表示する。
- 候補選択欄の近くに `入力サポート解除` チェックボックスを置く。
- チェックすると候補を再取得し、通常候補の下に `非推奨` グループを表示する。
- 非推奨候補は `⚠ 名前 (N回)` のように表示し、通常候補と見分けられるようにする。
- 候補の備考表示は従来通り、選択中のメンバーに備考がある場合だけ表示する。

## API Design

`GET /api/assignments/candidates` に `includeNonRecommended=true` を追加する。

- 未指定または `false`: 既存挙動を維持し、通常候補だけを返す。
- `true`: 有効メンバーのうち同日割り当て済みでない人を対象に、通常なら除外される人も返す。
- 非推奨理由は既存の `warnings` 配列へ追加する。
- 通常なら除外される理由は以下の警告として返す。
  - `unavailableDate`: その日に参加可能でない
  - `helperOnEventDay`: イベント日のヘルパー
  - `ebtEnglish`: EBT 日で他に通常参加機会がある英語メンバー
  - `gradeGroupMismatch`: 通常日の学年枠違い

## Boundaries

- 無効メンバーは候補に出さない。
- 同じ日にすでに割り当て済みのメンバーは候補に出さない。
- 確定時の既存バリデーションは維持する。API 側で禁止されている割り当ては、候補に出ても確定時に弾かれる。
- 自動生成ロジックは変更しない。

## Testing

- API 統合テストで、通常時は非推奨候補が返らず、`includeNonRecommended=true` では警告付きで返ることを確認する。
- フロントエンド用の軽量 DOM テストで、チェックボックス切り替え時に非推奨グループが追加されることを確認する。
